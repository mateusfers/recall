Cap. 1 — Introdução

Funções do Sistema Operacional

📌 Conceito Principal

O SO tem duas funções principais:

  1. Gerenciador de Recursos: gerencia CPU, memória, disco, E/S.
  2. Máquina Estendida: fornece abstrações (processos, arquivos, espaços de endereçamento) mais convenientes que o hardware.
💡 Fonte: Livro (Seção 1.1) + Slides

📖 Explicação Detalhada

O SO esconde a complexidade do hardware. Ex: em vez de lidar com setores de disco, você lida com arquivos. Em vez de lidar com interrupções de rede, você lida com sockets.

Como gerenciador de recursos, o SO decide quem usa a CPU, quem aloca memória, quem usa a impressora. Como máquina estendida, ele oferece uma interface limpa e consistente.

🔑 Os clientes reais do SO

São os programas aplicativos (via programadores). Eles lidam diretamente com as abstrações fornecidas pela interface do usuário (shell ou GUI).

🧠Active Recall

1) Gerenciador de Recursos — gerencia CPU, memória, disco, E/S.
2) Máquina Estendida — fornece abstrações (processos, arquivos, espaços de endereçamento).
🧠Active Recall
Quem são os "clientes reais" do sistema operacional?
Os programas aplicativos (via programadores). Eles lidam com as abstrações fornecidas pela interface do usuário (shell ou GUI).
❓

Por quê? Por que o SO precisa fornecer uma "máquina estendida" em vez de deixar o programador lidar direto com o hardware?

Porque o hardware é complexo, feio e cheio de detalhes. O SO cria abstrações limpas (arquivos, processos) que tornam a programação muito mais simples e portável.

CP/M, MS-DOS, Windows, Mac OS, Linux.

1990–presente5ª Geração — Móveis

Symbian, Android, iOS.

5ª Geração: Computadores móveis. Symbian, Android, iOS.

Cap. 1 — Introdução

Hardware de Computadores

📌 Conceito Principal

Um computador é composto por:

  • CPU — busca, decodifica, executa. Registradores, PC, PSW.
  • Memória — hierarquia: registradores → cache → RAM → disco.
  • Discos — armazenamento não volátil. Trilhas, setores, cilindros.
  • Dispositivos de E/S — controlador + dispositivo. Drivers.
  • Barramentos — PCIe, USB, SATA, DMI.
💡 Fonte: Livro (Seção 1.3) + Slides

📖 Explicação Detalhada

CPU: ciclo básico = buscar instrução, decodificar, executar. Registradores gerais + PC + PSW. Pipeline (múltiplos estágios). Superescalar (múltiplas unidades). Multithreading (hyperthreading). Multinúcleo.

Memória: hierarquia de camadas. Registradores (rápidos, caros, pequenos) → Cache (L1, L2, L3) → RAM → Disco.

Discos: pratos metálicos girando. Braço mecânico. Trilhas, setores (512 bytes), cilindros. Tempo de busca, atraso rotacional, taxa de transferência.

E/S: controlador + dispositivo. Drivers. E/S mapeada na memória ou portas de E/S. DMA.

Barramentos: PCIe (serial, ponto a ponto), USB, SATA, DMI. Barramento principal, barramentos secundários.

🔑 Conceitos-Chave

Pipeline

Múltiplas instruções em estágios diferentes. Ex: busca, decodificação, execução.

Superescalar

Múltiplas unidades de execução. Instruções executadas fora de ordem.

Hyperthreading

CPU mantém estado de 2 threads e alterna em nanossegundos.

Multinúcleo

Vários processadores completos no mesmo chip.

Cache

L1, L2, L3. Dados muito usados. Cache hit vs cache miss.

DMA

Acesso direto à memória. CPU não participa da transferência.

🧠Active Recall
O que é pipeline e qual sua vantagem?
Pipeline divide a execução em estágios (busca, decodificação, execução). Enquanto uma instrução executa, outra é decodificada e outra buscada. Vantagem: aumenta o throughput (instruções por segundo).
🧠Active Recall
O que é DMA e por que ele é importante para a multiprogramação?
DMA (Direct Memory Access) permite que dispositivos de E/S transfiram dados diretamente para a memória sem a CPU. Importância: a CPU fica livre para executar outros processos enquanto a E/S acontece.
🧠Active Recall
Qual a hierarquia de memória (da mais rápida para a mais lenta)?
Registradores → Cache (L1, L2, L3) → RAM → Disco.

Cap. 1 — Introdução

Chamadas de Sistema

📌 Conceito Principal

Chamadas de sistema são a interface entre programas de usuário e o SO. Elas permitem que o programa solicite serviços ao núcleo (kernel).

💡 Fonte: Livro (Seção 1.6) + Slides

🔑 Categorias de Chamadas (UNIX/POSIX)

Gerenciamento de Processos

fork(), execve(), exit(), waitpid()

Gerenciamento de Arquivos

open(), close(), read(), write(), lseek(), stat()

Gerenciamento de Diretórios

mkdir(), rmdir(), link(), unlink(), mount()

Diversas

chdir(), chmod(), kill(), time()

🔄 Como funciona uma chamada de sistema (11 passos)

  1. Programa empilha parâmetros (read)
  2. Chama a rotina de biblioteca read
  3. Rotina coloca o número da chamada no registrador
  4. Executa instrução TRAP (muda para modo núcleo)
  5. Núcleo examina o número da chamada
  6. Despacha para o tratador correto
  7. Tratador executa a chamada
  8. Retorna para a rotina de biblioteca
  9. Retorna para o programa do usuário
  10. Programa limpa a pilha
  11. Continua execução

🔑 Modo Núcleo vs Modo Usuário

Modo NúcleoModo Usuário
Todas as instruçõesSubconjunto de instruções
Acesso a todo hardwareE/S e proteção proibidas
Sistema operacionalProgramas de usuário
🧠Active Recall
Qual a diferença entre modo núcleo e modo usuário?
Núcleo: a CPU pode executar todas as instruções e acessar todo o hardware.
Usuário: apenas um subconjunto. Instruções de E/S e proteção de memória são proibidas.
🧠Active Recall
O que é uma instrução TRAP?
Instrução que muda do modo usuário para o modo núcleo e transfere o controle para o SO. Usada em chamadas de sistema.

Estruturas de Sistemas Operacionais (6 tipos)

📌 Conceito Principal

📦 Monolítica

Tudo em um único executável. Eficiente, mas difícil de manter.

🥞 Camadas

Hierarquia: cada camada sobre a anterior. Isolamento, mas overhead.

⚛️ Micronúcleo

Mínimo no núcleo; resto em user space. Confiável, mas lento.

👥 Cliente-Servidor

Clientes pedem, servidores atendem. Distribuição.

💻 Máquina Virtual

Clona o hardware. Executa vários SOs.

🔧 Exonúcleo

Aloca recursos diretamente. Menos overhead.

💡 Fonte: Livro (Seção 1.7) + Slides

📖 Explicação Detalhada

Monolítica: todos os módulos compilados e linkados em um único programa. Ex: MS-DOS, UNIX.

Camadas: hierarquia (THE, MULTICS). Cada camada oferece serviços à camada superior.

Micronúcleo: mínimo no núcleo (MINIX 3, QNX). Drivers e servidores em user space.

Cliente-Servidor: clientes pedem, servidores atendem. Comunicação por mensagens.

Máquina Virtual: VM/370, VMware, KVM, VirtualBox.

Exonúcleo: aloca recursos diretamente, sem mapeamento.

🧠Active Recall
Qual estrutura é "tudo em um único executável"?
Monolítica. Todos os módulos são compilados e linkados em um único programa executável.
🧠Active Recall
Qual a vantagem do micronúcleo sobre o monolítico?
Apenas o mínimo roda em modo núcleo. Drivers e servidores rodam em user space. Se um driver falha, não derruba o sistema inteiro. Maior confiabilidade.
❓

Por quê? Por que o micronúcleo é mais confiável que o monolítico?

Porque apenas o mínimo roda em modo núcleo. Drivers e servidores rodam em user space. Se um driver falha, não derruba o sistema inteiro.

Conceitos: Processos, Espaços, Arquivos

📌 Conceitos-Chave

🏃 Processo

Programa em execução. Tem espaço de endereçamento, registradores, PC, pilha.

💾 Espaço de Endereçamento

Lista de endereços que o processo pode usar (0 a máximo).

📁 Arquivo

Abstração para dados. Nome, estrutura, tipo, acesso, atributos, operações.

🔑 Proteção UNIX

Arquivos UNIX são protegidos por 9 bits: rwx para dono, grupo e outros.

Ex: rwxr-x--x → dono lê/escreve/executa, grupo lê/executa, outros executam.

🔑 Pipes

Um pipe é uma espécie de pseudoarquivo que conecta dois processos. O que um escreve, o outro lê. Ex: cat file | grep "tree".

  • close() — fecha arquivo
  • read() — lê dados
  • write() — escreve dados
  • lseek() — move ponteiro
  • stat() — obtém informações

Cap. 2 — Processos

Processos (Conceito)

📌 Conceito Principal

Um processo é uma instância de um programa em execução. Inclui:

  • Contador de programa (PC)
  • Registradores
  • Variáveis
  • Espaço de endereçamento
  • Arquivos abertos
  • Sinais, alarmes, etc.
💡 Fonte: Livro (Seção 2.1) + Slides (Cap2-Sigaa-Parte01)

📖 Explicação Detalhada

Um processo é uma abstração de um programa em execução. Ele dá suporte a operações (pseudo) concorrentes mesmo quando há apenas uma CPU disponível, transformando uma única CPU em múltiplas CPUs virtuais.

Diferenciação entre programa e processo:

  • Programa: entidade estática e permanente. Sequência de instruções. Passivo sob o ponto de vista do SO.
  • Processo: entidade dinâmica e efêmera (transitória). Altera seu estado à medida que avança sua execução. Composto por programa (código), dados e contexto (valores).

🔑 Criação de Processos (4 eventos)

  1. Inicialização do sistema — processos de primeiro plano (interagem com usuário) e de segundo plano (daemons).
  2. Chamada de sistema de criação — ex: fork().
  3. Solicitação do usuário — digitar um comando ou clicar em um ícone.
  4. Início de uma tarefa em lote — sistemas em lote.

🔑 Término de Processos (4 condições)

  1. Saída normal (voluntária) — o processo terminou seu trabalho.
  2. Erro fatal (involuntário) — ex: divisão por zero.
  3. Saída por erro (voluntária) — ex: arquivo não encontrado.
  4. Morto por outro processo (involuntário) — ex: kill.

🔑 Hierarquias de Processos

Em UNIX, processos formam uma hierarquia (árvore) com init na raiz. Em Windows, não há hierarquia.

🧠Active Recall
Qual a diferença entre programa e processo?
Programa: entidade estática e permanente (sequência de instruções).
Processo: entidade dinâmica e efêmera (programa em execução, com estado).
🧠Active Recall
Quais são os 4 eventos que criam processos? E as 4 condições de término?
Criação: 1) Inicialização do sistema, 2) Chamada de sistema, 3) Solicitação do usuário, 4) Início de tarefa em lote.
Término: 1) Saída normal, 2) Erro fatal, 3) Saída por erro, 4) Morto por outro processo.

🔑 Processos Suspensos

Razões para suspender um processo:

  • Swapping: SO libera memória para novo processo.
  • Solicitação do usuário: depuradores.

Porque quando o evento ocorre, o processo volta para Pronto. Só depois o escalonador pode escolhê-lo para Executando. Ele precisa esperar na fila de prontos.

fork() e Criação de Processos

📌 Conceito Principal

fork() é a única chamada de sistema UNIX para criar um novo processo. Ela cria uma cópia exata do processo pai.

💡 Fonte: Slides (Cap2-Sigaa-Parte02) + Livro

🔑 Retorno de fork()

ContextoValor retornado
Processo filho0
Processo paiPID do filho (> 0)
Erronegativo

⚠️ Regra de Ouro

Cada fork() incondicional DOBRA o número de processos.
Após n forks, existem 2ⁿ processos.
Nº de forksNº de processosCálculo
012⁰ = 1
122¹ = 2
242² = 4
382³ = 8
4162⁴ = 16

🔑 Comportamento das Variáveis

Cada processo tem seu próprio espaço de endereçamento. Alterações em variáveis são locais a cada processo (copy-on-write). O valor inicial é o mesmo, mas cada um evolui independentemente.

🔑 Estrutura típica

pid_t pid = fork();
if (pid == 0) {
    // Código do FILHO (pid == 0)
} else {
    // Código do PAI (pid > 0)
}

⚠️ Pegadinhas

1. Variáveis são independentes entre pai e filho.
2. Em if/else if/else, a primeira condição verdadeira ganha. Um filho herda pid = 0 e cai no if (pid == 0) primeiro.
3. A ordem de impressão é indeterminada, mas os valores são determinísticos.
🧠Active Recall
Quantos processos filhos são criados por 3 forks incondicionais?
2³ = 8 processos totais → 1 pai + 7 filhos.
🧠Active Recall
O que fork() retorna no processo filho?
Retorna 0 no processo filho.

Cap. 2 — Processos

Threads

📌 Conceito Principal

Um thread é um fluxo único de controle sequencial dentro de um programa. É como um "miniprocesso" que compartilha o espaço de endereçamento com outros threads do mesmo processo.

💡 Fonte: Livro (Seção 2.2) + Slides (Cap02-Parte02)

🔑 Por que usar threads?

  • Paralelismo: múltiplas atividades simultâneas.
  • Leveza: criar thread é 10-100x mais rápido que criar processo.
  • Desempenho: sobreposição de E/S e computação.
  • Compartilhamento: threads compartilham memória.

🔑 Itens por Processo vs por Thread

Por PROCESSOPor THREAD
Espaço de endereçamentoContador de programa (PC)
Variáveis globaisRegistradores
Arquivos abertosPilha
Processos filhosEstado
Alarmes pendentes
Sinais e tratadores

🔑 Implementação

👤 User-level

Biblioteca gerencia. Rápido. Problema: chamadas bloqueantes travam tudo.

⚙️ Kernel-level

SO gerencia. Mais lento. Chamadas bloqueantes não travam o processo todo.

🔀 Híbrido

Multiplexa threads de usuário sobre threads de kernel.

🔑 Exemplo de uso

Servidor web multithread: um thread despachante lê requisições e passa para threads operários. Cada operário verifica o cache, lê do disco, retorna ao cliente.

Processador de texto: 3 threads — um interage com usuário, um reformata, um faz backup.

🧠Active Recall
O que é compartilhado entre threads do mesmo processo? O que é exclusivo de cada thread?
Compartilhado (por processo): espaço de endereçamento, variáveis globais, arquivos abertos, processos filhos.

Exclusivo (por thread): PC, registradores, pilha, estado.
🧠Active Recall
Qual a maior vantagem de threads de usuário? E a maior desvantagem?
Vantagem: rápida criação/troca (sem chamadas de sistema).
Desvantagem: uma chamada bloqueante trava o processo inteiro (o núcleo não sabe dos threads).

Cap. 2 — Processos

Comunicação entre Processos (IPC)

📌 Conceito Principal

Processos precisam se comunicar. Três questões fundamentais:

  1. Como um processo passa informação para outro?
  2. Como garantir que não interfiram entre si?
  3. Como garantir a sequência correta (dependências)?
💡 Fonte: Livro (Seção 2.3) + Slides (Cap02-ComunicaçãoInterprocAnt)

⚠️ Condições de Corrida

Ocorrem quando dois ou mais processos acessam dados compartilhados e o resultado depende de quem executa primeiro.

Exemplo: Spooler de impressão — dois processos leem o mesmo slot livre (7) e ambos tentam usá-lo. O processo B nunca recebe sua impressão.

🔑 Região Crítica

Trecho de código que acessa recursos compartilhados. Deve ser executado por apenas um processo por vez.

4 condições para uma boa solução:
  1. Exclusão mútua: nunca dois na RC juntos
  2. Sem suposições: não depende de velocidades/nº CPUs
  3. Fora da RC não bloqueia
  4. Sem espera infinita
🧠Active Recall
O que é uma condição de corrida?
Situação onde dois ou mais processos leem/escrevem dados compartilhados e o resultado depende de quem executa primeiro.
🧠Active Recall
Quais são as 4 condições para uma boa solução de exclusão mútua?
1) Exclusão mútua
2) Sem suposições de velocidade/nº CPUs
3) Fora da RC não bloqueia
4) Sem espera infinita

Cap. 2 — Processos

Exclusão Mútua (Soluções)

📌 Conceito Principal

Várias soluções foram propostas para garantir exclusão mútua. Umas usam espera ocupada, outras usam bloqueio.

💡 Fonte: Livro (Seção 2.3.3) + Slides (Cap02-ComunicaçãoInterprocAnt)

🔑 Soluções com Espera Ocupada

❌ Desabilitar Interrupções

Funciona em monoprocessador. Não funciona em multicore. Processo pode esquecer de reabilitar.

❌ Variável Lock

Condição de corrida: ambos leem 0 antes de escrever 1.

⚠️ Strict Alternation

Usa turn. Viola Condição 3 (fora da RC bloqueia).

✅ Peterson

Combina interested[] + turn. Funciona com 2 processos.

✅ TSL

Instrução atômica de hardware. Funciona em multicore.

🔑 Strict Alternation (Código)

// P0
while (turn != 0) { }
/* RC */
turn = 1;   // passa a vez

// P1
while (turn != 1) { }
/* RC */
turn = 0;   // passa a vez
⚠️ Viola Condição 3: Se P0 sai da RC e P1 está na região não-crítica, P0 não pode entrar de novo. P1 (fora da RC) bloqueia P0.

🔑 Peterson (Código)

// Processo i (0 ou 1)
int other = 1 - i;
interested[i] = TRUE;
turn = i;
while (turn == i && interested[other] == TRUE) { }
/* RC */
interested[i] = FALSE;

🔑 TSL (Test and Set Lock)

enter_region:
    TSL REGISTER, LOCK    // copia lock p/ reg, lock=1
    CMP REGISTER, #0      // lock era 0?
    JNE enter_region      // se não, volta
    RET

leave_region:
    MOVE LOCK, #0         // lock=0
    RET
🧠Active Recall
Qual condição o Strict Alternation viola? Por quê?
Viola a Condição 3 (fora da RC não bloqueia). Se P0 sai da RC e P1 está na região não-crítica, P0 não pode entrar de novo. P1 (fora da RC) bloqueia P0.
🧠Active Recall
Qual a vantagem do TSL sobre as outras soluções de espera ocupada?
TSL é uma instrução atômica de hardware. Funciona em multicore (trava o barramento de memória). As outras soluções não funcionam em multicore.

Cap. 2 — Processos

Semáforos e Mutexes

📌 Conceito Principal

Semáforo é uma variável inteira com 2 operações atômicas:

  • down(s) (ou P): espera/decrementa
  • up(s) (ou V): libera/incrementa
💡 Fonte: Livro (Seção 2.3.5) + Slides (Cap02-ComunicaçãoInterprocAnt, Slide 53-64)

🔑 Funcionamento

down(s):
    if (s > 0) {
        s = s - 1;         // decrementa
    } else {
        bloqueia o processo; // espera na fila
    }

up(s):
    if (existe processo bloqueado) {
        acorda um deles;   // continua
    } else {
        s = s + 1;         // incrementa
    }

🔑 Tipos de Semáforos

Binário (Mutex)

Valores 0 ou 1. Usado para exclusão mútua.

Contador

Valores > 1. Usado para controlar pool de recursos (ex: 5 impressoras).

🔑 Mutexes

Versão simplificada do semáforo binário. Usado para exclusão mútua.

  • mutex_lock — adquire a trava ou bloqueia
  • mutex_unlock — libera a trava
  • mutex_trylock — tenta adquirir, mas não bloqueia

🔑 Futexes

Implementação do Linux que combina uma trava giratória (rápida) com uma fila de espera (lenta). Evita chamadas de sistema quando não há contenção.

🧠Active Recall
O que down() e up() fazem em um semáforo?
down(s): se s > 0, decrementa. Se s = 0, bloqueia o processo.
up(s): se há processo bloqueado, acorda um. Se não, incrementa.
🧠Active Recall
Qual a diferença entre semáforo binário e contador?
Binário: só assume 0 ou 1. Usado para exclusão mútua (mutex).
Contador: assume valores > 1. Usado para controlar pool de recursos.

Monitores

📌 Conceito Principal

Monitor é uma primitiva de alto nível para sincronizar processos. É um conjunto de procedimentos, variáveis e estruturas de dados agrupados em um módulo.

Propriedade: apenas um processo pode estar ativo dentro do monitor por vez.

💡 Fonte: Livro (Seção 2.3.7) + Slides (Cap02-ComunicaçãoInterprocAnt, Slide 66-69)

🔑 Variáveis de Condição

Permitem que um processo espere dentro do monitor.

  • wait(c) — bloqueia o processo na variável de condição c
  • signal(c) — acorda um processo bloqueado em c
⚠️ Diferença de semáforos: Variáveis de condição NÃO têm memória. Se um signal é enviado sem ninguém esperando, ele é perdido.

🔑 Exemplo (Produtor/Consumidor com Monitores)

monitor ProducerConsumer
    condition full, empty;
    integer count;

    procedure insert(item):
        if count = N then wait(full);
        insert_item(item);
        count := count + 1;
        if count = 1 then signal(empty);

    procedure remove():
        if count = 0 then wait(empty);
        remove_item();
        count := count - 1;
        if count = N-1 then signal(full);
end monitor
🧠Active Recall
O que é um monitor e qual sua principal propriedade?
Monitor é uma primitiva de alto nível para sincronização. Propriedade: apenas um processo pode estar ativo dentro do monitor por vez. O compilador garante a exclusão mútua.
🧠Active Recall
O que wait() e signal() fazem em um monitor?
wait(c): bloqueia o processo na variável de condição c.
signal(c): acorda um processo bloqueado em c.
❓

Por quê? Por que variáveis de condição não têm memória, diferente de semáforos?

Porque em monitores, se um signal é enviado sem ninguém esperando, ele é perdido. Isso simplifica a implementação. Cabe ao programador verificar o estado com variáveis.

Cap. 2 — Processos

Problema Produtor/Consumidor

📌 Conceito Principal

Dois processos compartilham um buffer de tamanho fixo N:

  • Produtor: insere itens no buffer
  • Consumidor: remove itens do buffer

Problema: Produtor dorme se buffer cheio; consumidor dorme se buffer vazio.

💡 Fonte: Livro (Seção 2.3.4) + Slides (Cap02-ComunicaçãoInterprocAnt, Slide 42-50)

🔑 Solução com Semáforos

semaphore mutex = 1;   // exclusão mútua
semaphore empty = N;   // slots vazios
semaphore full = 0;    // slots ocupados

void producer() {
    while (TRUE) {
        item = produce_item();
        down(&empty);     // espera slot vazio
        down(&mutex);     // entra na RC
        insert_item(item);
        up(&mutex);       // sai da RC
        up(&full);        // sinaliza item
    }
}

void consumer() {
    while (TRUE) {
        down(&full);      // espera item
        down(&mutex);     // entra na RC
        item = remove_item();
        up(&mutex);       // sai da RC
        up(&empty);       // sinaliza slot vazio
        consume_item(item);
    }
}

⚠️ Pegadinha

Inverter a ordem dos down (mutex antes de empty) causa DEADLOCK!
Se o buffer está cheio, o produtor pega o mutex e bloqueia em empty. O consumidor não consegue pegar o mutex para liberar espaço.
🧠Active Recall
Quais são os 3 semáforos usados no produtor/consumidor? O que cada um faz?
mutex: exclusão mútua no buffer (1).
empty: conta slots vazios (N).
full: conta slots ocupados (0).
🧠Active Recall
O que acontece se inverter a ordem dos down (mutex antes de empty)?
DEADLOCK. Se o buffer está cheio, o produtor pega o mutex e bloqueia em empty. O consumidor não consegue pegar o mutex para liberar espaço.

Cap. 2 — Processos

Jantar dos Filósofos

📌 Conceito Principal

5 filósofos, 5 garfos. Cada um precisa de 2 garfos para comer. Alternam entre pensar e comer.

Desafio: Como evitar deadlock?

💡 Fonte: Livro (Seção 2.5.1) + Slides (Cap02-ProblemasClassicos)

❌ Solução Ingênua (ERRADA)

void philosopher(int i) {
    while (TRUE) {
        think();
        take_fork(i);           // pega esquerdo
        take_fork((i+1) % N);   // pega direito
        eat();
        put_fork(i);
        put_fork((i+1) % N);
    }
}
Problema: Se todos pegarem o garfo esquerdo ao mesmo tempo, nenhum consegue pegar o direito → DEADLOCK.

✅ Solução Correta (com Estados)

#define THINKING 0
#define HUNGRY 1
#define EATING 2

int state[N];
semaphore mutex = 1;
semaphore s[N];

void philosopher(int i) {
    while (TRUE) {
        think();
        take_forks(i);
        eat();
        put_forks(i);
    }
}

void take_forks(int i) {
    down(&mutex);
    state[i] = HUNGRY;      // ← AVISA que quer comer
    test(i);
    up(&mutex);
    down(&s[i]);            // bloqueia se não conseguiu
}

void put_forks(int i) {
    down(&mutex);
    state[i] = THINKING;
    test(LEFT);
    test(RIGHT);
    up(&mutex);
}

void test(int i) {
    if (state[i] == HUNGRY &&
        state[LEFT] != EATING &&
        state[RIGHT] != EATING) {
        state[i] = EATING;
        up(&s[i]);
    }
}

🔑 Por que HUNGRY é essencial?

A linha state[i] = HUNGRY é o "pedido de comida" do filósofo. A rotina test() verifica state[i] == HUNGRY para decidir se o filósofo pode comer.

Sem HUNGRY: test() nunca libera o filósofo (state[i] ainda é THINKING).

🔑 Por que a solução funciona?

  • Sem deadlock: um filósofo só come se nenhum vizinho come.
  • Sem inanição: quando um filósofo termina, ele libera os vizinhos.
  • Máximo paralelismo: até 2 filósofos (não vizinhos) podem comer ao mesmo tempo.
🧠Active Recall
Por que a solução ingênua do jantar dos filósofos causa deadlock?
Porque se todos os 5 filósofos pegarem o garfo esquerdo ao mesmo tempo, nenhum consegue pegar o direito (que está com o vizinho). Ninguém solta, ninguém pega → DEADLOCK.
🧠Active Recall
Por que a variável de estado é configurada para HUNGRY na rotina take_forks?
Para indicar que o filósofo QUER COMER. A rotina test() verifica state[i] == HUNGRY para decidir se pode comer. Sem HUNGRY, test() nunca libera o filósofo.

Você domina este conceito?

Leitores/Escritores

📌 Conceito Principal

Múltiplos leitores podem ler simultaneamente. Escritor tem acesso exclusivo.

  • Vários leitores podem ler juntos
  • Escritor precisa de acesso exclusivo
  • Leitor + Escritor = conflito
💡 Fonte: Livro (Seção 2.5.2) + Slides (Cap02-ProblemasClassicos)

🔑 Solução (Prioridade para Leitores)

semaphore mutex = 1;   // protege rc
semaphore db = 1;      // protege o banco
int rc = 0;            // nº de leitores

void reader() {
    down(&mutex);
    rc++;
    if (rc == 1) down(&db);   // primeiro leitor trava
    up(&mutex);
    read_data();
    down(&mutex);
    rc--;
    if (rc == 0) up(&db);     // último leitor libera
    up(&mutex);
}

void writer() {
    down(&db);
    write_data();
    up(&db);
}

🔑 As 3 Variações

1. Prioridade Leitores

Leitores entram enquanto houver um ativo. Escritores podem sofrer inanição.

2. Prioridade Escritores

Escritor bloqueia leitores subsequentes. Leitores podem sofrer inanição.

3. Sem Prioridade

Fila FIFO. Justo, mas ambos podem sofrer inanição.

🧠Active Recall
No problema dos leitores/escritores, o que o contador rc faz?
rc conta o número de leitores ativos. O primeiro leitor (rc=1) trava o banco (down(&db)). O último leitor (rc=0) destrava (up(&db)).

📌 Conceitos Principais

Escalonador

Escolhe qual processo executar.

Despachante (Dispatcher)

Salva/restaura contexto e troca para o processo escolhido.

Preemptivo

Processo pode ser interrompido (RR, SRTN).

Não Preemptivo

Processo executa até terminar/bloquear (FCFS, SJN).

💡 Fonte: Livro (Seção 2.4) + Slides (Cap2-Escalonamento)

📐 Fórmulas Essenciais

Turnaround = Conclusão − Chegada

Espera = Turnaround − Execução

Média = Σ(esperas) / n

🔑 Algoritmos

🔑 Round Robin (Regras)

  1. Fila inicial: ordem de chegada
  2. Execução: primeiro da fila executa por 1 quantum
  3. Se terminou: sai da fila ✅
  4. Se não terminou: volta para o fim da fila
  5. Novos processos: entram no fim quando chegam
  6. Ordem: preemptado primeiro, depois novos
  7. Fila vazia: CPU fica ociosa até próximo chegar

⚠️ Pegadinhas

1. Chegada ≠ 0: espere o processo chegar.
2. Turnaround ≠ Espera: não confunda!
3. Empate: use FCFS (ordem de chegada).
4. Quantum muito pequeno: muitas trocas, overhead.
5. Quantum muito grande: vira FCFS.

Turnaround = Conclusão − Chegada
Espera = Turnaround − Execução

Melhor: SJF (menor tempo médio).
Pior: RR com quantum pequeno (muitas trocas).

Cap. 6 — Impasse

Definição e 4 Condições

📌 Definição

Impasse (deadlock) é uma situação onde um conjunto de processos está bloqueado para sempre, cada um esperando por um recurso que outro processo do conjunto possui.

💡 Fonte: Livro (Seção 6.1-6.2) + Slides (Deadlocks.pdf)

🔑 As 4 Condições (Coffman et al., 1971)

1. Exclusão Mútua

Cada recurso está associado a exatamente um processo ou está disponível.

2. Posse e Espera

Processos que possuem recursos podem solicitar novos recursos.

3. Não Preempção

Recursos não podem ser tomados à força; devem ser liberados explicitamente.

4. Espera Circular

Existe uma cadeia circular de processos esperando.

⚠️ TODAS as 4 devem estar presentes! Se uma faltar, NÃO há impasse.

🔑 Recursos Preemptíveis vs Não-Preemptíveis

Preemptíveis

Podem ser retirados sem prejuízo. Ex: memória, CPU.

Não-Preemptíveis

Não podem ser retirados. Ex: CD-ROM, unidades de fita.

🔑 Exemplo de Impasse

Processo A tem R e quer S. Processo B tem S e quer R. Nenhum solta, nenhum pega → impasse.

Processo C espera T (que está com D). Processo D espera U (que está com C). Ciclo: C → T → D → U → C.

🧠Active Recall
Quais são as 4 condições necessárias para um impasse?
1) Exclusão mútua
2) Posse e espera
3) Não preempção
4) Espera circular
🧠Active Recall
Defina impasse.
Um conjunto de processos está em impasse se cada processo no conjunto está esperando por um evento que apenas outro processo do conjunto pode causar.
❓

Por quê? Por que a ausência de qualquer uma das 4 condições evita o impasse?

Porque as 4 são necessárias. Se uma não existe, o ciclo de espera não se forma. Ex: sem espera circular, não há ciclo.

Grafos de Alocação de Recursos

📌 Conceito Principal

Grafos representam deadlocks:

  • Círculos = processos
  • Quadrados = recursos
  • Seta P → R = processo solicita recurso
  • Seta R → P = recurso alocado a processo
💡 Fonte: Livro (Seção 6.2.2) + Slides (Deadlocks.pdf, Slide 8-9)

🔑 Ciclo = Impasse

Se o grafo contém um ciclo, há um impasse (presumindo um recurso de cada tipo).

Exemplo: P1 → R1 → P2 → R2 → P1

🔑 Wait-For Graph (Grafo de Espera)

Simplificação: só processos. Aresta P → Q significa que P espera recurso de Q.

Algoritmo:

  1. Criar nó para cada processo
  2. Para cada processo que espera recurso:
    • Identificar recurso e dono
    • Criar aresta P → Q
  3. DFS para detectar ciclo
  4. Se ciclo → IMPASSE
🧠Active Recall
O que significa um ciclo em um grafo de alocação de recursos?
Significa que há um IMPASSE envolvendo os processos e recursos no ciclo (presumindo um recurso de cada tipo).
🧠Active Recall
O que é um wait-for graph?
Grafo simplificado com apenas processos. Aresta P → Q significa que P espera recurso de Q. Se houver ciclo → impasse.

Cap. 6 — Impasse

Detecção de Impasse

📌 Conceito Principal

Deixa o impasse ocorrer e depois detecta.

💡 Fonte: Livro (Seção 6.4) + Slides (Deadlocks.pdf, Slide 13-24)

🔑 Detecção com 1 Recurso de Cada Tipo

Usa grafo de espera (wait-for graph):

  1. Criar nó para cada processo
  2. Para cada processo que espera recurso, criar aresta P → Q
  3. DFS para detectar ciclo
  4. Se ciclo → IMPASSE

🔑 Detecção com Múltiplos Recursos

Usa matrizes:

  • E = recursos existentes (total)
  • A = recursos disponíveis
  • C = matriz de alocação atual
  • R = matriz de requisições (Necessário)

Necessário = Máximo − Alocado

Disponível = E − Total Alocado

Algoritmo:

  1. Procure processo com R ≤ A
  2. Se encontrar: A = A + C[i], marque como concluído
  3. Repita até todos terminarem (sem impasse) ou ninguém poder executar (impasse)

🔑 Exemplo

3 processos, 4 recursos. E = (4,2,3,1). A = (2,1,0,0). C e R matrizes.

P3 pode rodar → A = (2,2,2,0) → P2 pode rodar → A = (4,2,2,1) → P1 pode rodar.

🧠Active Recall
Como funciona a detecção de impasse com 1 recurso de cada tipo?
Usa grafo de espera: criar nó para cada processo, arestas P→Q se P espera recurso de Q. Se houver ciclo → IMPASSE.
🧠Active Recall
Quais são as 4 matrizes/vetores usados na detecção com múltiplos recursos?
E (recursos existentes), A (disponíveis), C (alocação atual), R (requisições).

Você domina este conceito?

Cap. 6 — Impasse

Algoritmo do Banqueiro

📌 Conceito Principal

Algoritmo de evasão que verifica se um estado é SEGURO antes de conceder recursos.

  • Estado seguro: existe sequência onde todos terminam
  • Estado inseguro: não há garantia
💡 Fonte: Livro (Seção 6.5) + Slides (Deadlocks.pdf, Slide 27-35)

🔑 Estruturas

SímboloSignificado
ERecursos existentes (total)
ARecursos disponíveis
CMatriz de alocação atual
RMatriz de requisições (Necessário)

📐 Fórmulas Essenciais

Necessário = Máximo − Alocado

Disponível = Total Existente − Total Alocado

Invariante: ΣC + A = E

🔑 Passo a Passo

  1. Calcular Necessário = Máximo − Alocado
  2. Anotar Disponível (A)
  3. Procurar processo com Necessário ≤ Disponível
  4. Se encontrar: A = A + Alocado[i], marcar como concluído
  5. Repetir até:
    • Todos executarem → SEGURO ✅
    • Sobrar processo → INSEGURO ❌

⚠️ Pegadinhas

1. Necessário = Máximo − Alocado (SEMPRE calcule!)
2. Estado inseguro ≠ deadlock (pode nunca ocorrer)
3. Após conceder: subtraia do disponível, some ao alocado, subtraia do necessário
4. Qualquer ordem serve se todos terminarem
🧠Active Recall
O que é um estado seguro no algoritmo do banqueiro?
Estado onde existe uma sequência de execução onde todos os processos terminam. A partir de um estado seguro, há garantia de que não haverá deadlock.
🧠Active Recall
Por que o algoritmo do banqueiro é classificado como evasão e não detecção?
Porque ele age ANTES do deadlock ocorrer (verifica segurança antes de conceder). Detecção age DEPOIS (deixa ocorrer e detecta).

Você domina este conceito?

Cap. 6 — Impasse

Prevenção de Impasse

🔑 Ordenação de Recursos (Espera Circular)

Regra: Todos os processos devem solicitar recursos em ordem crescente.

Por que funciona: Nenhum processo pede recurso de número menor que os que já tem. Não forma ciclo.

Exemplo:

  • P1: M1 → M2 ✅ (já em ordem)
  • P2: M2 → M3 ✅ (já em ordem)
  • P3: M3 → M1 ❌ → Corrigir para M1 → M3
🧠Active Recall
Como prevenir impasse atacando a condição de espera circular?
Ordenar os recursos numericamente e exigir que todos os processos os solicitem em ordem crescente. Assim, nenhum processo pede recurso de número menor que os que já tem → não forma ciclo.
🧠Active Recall
Como atacar cada uma das 4 condições?
Exclusão Mútua: spool. Posse e Espera: requisitar tudo no início. Não Preempção: virtualizar. Espera Circular: ordenar recursos.

Cap. 6 — Impasse

Livelock e Inanição

📌 Conceito Principal

💀 Impasse (Deadlock)

Sistema NÃO progride. Todos bloqueados.

🔄 Livelock

Processos NÃO estão bloqueados, mas nenhum progride. Ex: dois processos tentando ser educados e dando passos laterais.

😢 Inanição (Starvation)

Sistema PROGRIDE, mas um processo espera para sempre.

💡 Fonte: Livro (Seção 6.7) + Slides (Deadlocks.pdf, Slide 37)

🔑 É possível ter:

  • Inanição SEM impasse? ✅ SIM (SJN com fluxo de curtos)
  • Impasse SEM inanição? ✅ SIM (todos esperando ativamente)

🔑 Exemplo de Livelock

Dois processos tentando ser educados: ambos dão um passo para o lado ao mesmo tempo, e continuam dando passos laterais, sem nunca progredir.

🧠Active Recall
Qual a diferença entre impasse e inanição?
Impasse: sistema NÃO progride (todos bloqueados).
Inanição: sistema PROGRIDE, mas 1 processo espera para sempre (postergado).
🧠Active Recall
O que é livelock?
Processos NÃO estão bloqueados, mas nenhum progride. Ex: dois processos tentando ser educados e dando passos laterais ao mesmo tempo. Diferente do impasse, os processos estão ativos.
